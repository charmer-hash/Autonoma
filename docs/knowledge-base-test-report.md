## 真实向量匹配检查

当前“产品文档”包含两份 `ready` 文档，共 9 个分片，全部有 1024 维向量：DOCX 已重建索引，由原来的 1 片变为按标题划分的 3 片；Markdown 按标题拆为 6 片。DOCX 的 `heading_path` 现能定位到“需求背景”“可抓取链接规范”“动态 URL 结构规范”。

| 测试问题 | 向量最高余弦相似度 | 修正后的结果 |
| --- | ---: | --- |
| 短剧详情页 All EP 标签添加内链 | 0.746 | 命中对应 DOCX。 |
| playlist fast back 404 的根因是什么 | 0.588 | 返回“结论”和“复现证据与原因”。 |
| playlist 快速返回 404 如何验收 | 0.649 | “验收步骤”排第 1。 |
| 火星探测器的燃料配方是什么 | 0.325 | 阈值过滤后 0 命中。 |

本轮发现关键词通道按文件名分数排序时，同一文件的各分片分数相同，容易偏向靠前章节；同时每文档最多返回 3 片，导致“验收步骤”或“复现证据与原因”被挤出最终结果。已改成先按正文相似度排序，对标题与问题共有的短语加分，并提高向量通道在 RRF 中的权重。针对上述问题的实际数据库复测通过，并新增标题排序单元测试。

已加入相对相似度过滤：纯向量候选若低于本轮最佳命中超过 0.1，则从向量通道移除；关键词通道仍可召回它。真实问题“播放列表404问题如何验收？”只返回播放列表文档，“短剧详情页 All EP 标签内链的动态 URL 规范是什么？”将对应 Word 章节排在首位；无关天气问题返回空命中。过滤差值和绝对阈值均为临时参数，后续需用标注集校准。

## 当前问题

1. 首次有效密钥复测发现向量 SQL 跳过 `$4` 参数，导致 PostgreSQL 报 `could not determine data type of parameter $4` 并静默降级。已修正参数编号，真实检索重新返回 `ok`，并加入单元断言。
2. 原先向量检索总会取最近片段，无关天气问题也命中“产品文档”。现加入默认余弦相似度 `0.5` 的临时阈值；相关问题仍命中，无关问题不命中。上线前需要用标注过的真实问题集校准阈值、Recall@5 和无答案误召回率，不能只凭这两个样本定最终参数。
3. 替换版本第一次测试遇到数据库瞬时 `ECONNRESET`。临时数据已清理；知识库只读查询和可重复删除操作已加入短暂重试，替换流程随后通过。跨网络的 DB/R2 双写仍需在更大规模故障注入中验证。
4. `http://localhost:8787/` 原先返回 404，现返回 API 状态信息；本地前端 `.env.local` 已指向 8787，两者均已验证。前端页面的人工点击、登录与文件选择交互尚未用浏览器自动化逐项验收。
5. 扫描版 PDF 的 OCR 暂无需求，也未配置 `MISTRAL_API_KEY`，因此没有测试 OCR。R2 删除失败的持久化重试队列和检索质量回归集仍待建设。

## 复测命令

```powershell
pnpm --filter server test
pnpm typecheck
cd apps/server
$env:AUTH_SESSION_SECRET=''
node --env-file=.env --import tsx scripts/knowledge-smoke.ts
node --env-file=.env --import tsx scripts/knowledge-smoke.ts --replace
```

`knowledge-smoke.ts` 会创建带随机名称的临时知识库，测试 R2 上传、后台索引、检索和 Agent 必查，然后清理测试对象；`--replace` 追加版本替换检查。它会调用真实服务并产生少量模型费用；仅在确认测试环境允许临时匿名数据时运行。`knowledge-db-smoke.ts` 验证数据库召回和必查无命中路径；`knowledge-auth-smoke.ts` 使用两个临时账号验证权限，运行时不要清空 `AUTH_SESSION_SECRET`。
